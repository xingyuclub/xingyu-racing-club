# 星屿配置后台

后台仅用于本机或受信任局域网。先创建本地凭据文件并设置密码：

```powershell
Copy-Item server/config/admin.example.json server/config/admin.local.json
# Edit server/config/admin.local.json and replace change-this-password.
npm install
npm run dev:api
npm run dev
```

开发时前台地址是 `http://127.0.0.1:5173/`，后台地址是 `http://127.0.0.1:5173/admin`。Vite 会把 `/api` 和 `/uploads` 转发给本地 API 服务。

生产模式执行 `npm run serve`，服务地址是 `http://127.0.0.1:3000/`，后台为 `http://127.0.0.1:3000/admin`。

运行时配置保存在 `server/data/site-config.json`；每次保存前的上一版位于 `server/data/site-config.json.bak`。上传的图片、视频和音频保存在 `server/storage/uploads/`，后台会返回可直接填写到配置中的 `/uploads/...` 路径。

`server/config/admin.local.json` 使用明文保存单个管理员账号和密码，仅限本地配置，绝不能提交、公开或部署到公网。会话保存在服务进程内，重启 API 服务后需重新登录。

## 新闻管理

- 已保存的新闻默认收起，只显示“标题 · 分类 · 日期”；点击右侧展开按钮后编辑，新增新闻会自动展开。
- “首页封面图上传”只控制首页资讯列表缩略图和详情页顶部封面，不会自动插入正文。
- 新闻分类在后台维护，支持新增、删除和改名；前台列表页的 Tab（“全部”+ 各分类）自动跟随。
- 正文工具栏支持撤销、重做、正文/二级/三级标题、字体、字号、文字颜色、粗体、斜体、下划线、对齐、列表、链接和换行。
- 点击“插入图片”可在当前光标处加入正文图片，并可重复上传多张；正文图片与首页封面图相互独立。
- 编辑器会同时保存安全 HTML 和兼容旧版的纯文本正文。旧新闻无需手动迁移，展开时会自动按原有换行显示。
- 正文图片只允许后台上传路径 `/uploads/` 或项目图片路径 `/images/`；外链图片、Base64 图片和不安全 HTML 会在服务端保存时移除。
- 编辑完成后点击页面底部“保存全部配置”。前台首页只展示置顶新闻（最多 5 条，无置顶时兜底最新 3 条）；点“查看更多新闻”进入 `#news` 列表页，按分类 Tab 切换；点条目进入 `#news/<id>` 独立详情页，详情页右上角“分享”按钮复制当前完整链接，可直接粘贴到微信群。

## 星屿积分榜

后台的“星屿积分榜”支持两种填写方式：直接在网页表格中逐行编辑，或下载 Excel 模板后批量导入。积分按具体日期填写，不再按周填写。

### 两套人员来源

- `roster` 是后台“成员管理”的当前成员，只用于前台阵容、成员资料、媒体和截图昵称匹配。
- `scoreMembers` 是独立的积分榜人物，只用于排行榜、日期积分、普通积分表和周末积分表。
- 首次历史 Excel 导入完全使用 Excel 中的昵称，不匹配、添加或修改 `roster`。
- 姓名去掉 `ˣʸ༩·` 前缀后相同即视为同一积分人物；跨周显示名采用最后一周 Excel 中的原文。
- 后续截图先按 `roster` 和别名识别当前成员，再通过成员管理中保存的“积分人物”绑定累计到已有 `scoreMembers` 身份；系统不会自动创建积分人物。
- 每个当前成员最多绑定一个已有积分人物，同一个积分人物不能被多个当前成员重复占用。未绑定或绑定失效时，截图批次会阻止提交。

首次或需要重新覆盖 KW27-KW31 时，在项目根目录执行：

```powershell
node scripts/import-legacy-score-workbook.js "C:/Users/Admin/Desktop/车队网站图片/星屿杯积分明细NEW.xlsx"
```

脚本只读取源 Excel，严格覆盖 `2026-06-29` 至 `2026-08-02` 的工作日和周末积分，保留范围外记录，并在写入前通过配置存储生成 `server/data/site-config.json.bak`。任何工作表解析错误或 `roster` 变化都会终止导入。

### 在线填写

1. 在“星屿积分榜”点击“新增明细”。
2. 从积分人物中选择姓名，填写日期、队内赛 3 局和开黑赛 3 局成绩。
3. “得分”和“总分”由系统自动计算，无需手填；总分是本周从周一开始累加到当天，每周一重置。
4. 检查无误后点击页面底部的“保存全部配置”。

### Excel 批量填写

1. 点击“下载模板”，获得包含 `积分明细` 和 `队员期初积分` 两张工作表的 `.xlsx` 文件。
2. 在 `积分明细` 中按日期逐行填写蓝色单元格；同一日期、同一队员只能有一行。
3. 在 `队员期初积分` 中修改积分人物的期初积分。积分人物没有后台编号时编号列保持空白，昵称用于识别，不要随意改动。
4. 回到后台点击“导入 Excel”，选择文件并先查看导入预览。
5. 预览无误后确认导入，再点击“保存全部配置”写入运行时配置。

“导出当前数据”会生成包含当前每日明细和期初积分的 Excel。导入时，Excel 中出现的日期会整体覆盖后台同日期数据，其他日期保留；旧版按周横向排列的表格不能直接导入，需要先整理为模板中的按日期纵向明细。

保存后刷新前台，首页积分榜按最新日期的“总分”倒序显示前 10 名；点击“查找”后可按日期查看六局成绩、得分和当天总分。

## 截图识别

截图识别功能用 AI 从比赛截图自动提取成绩，确认后写入积分榜。使用前需要在项目根目录创建 `.env`（参考 `.env.example`），填写 `OPENAI_API_KEY`；模型默认 `gpt-4o`，可在 `OPENAI_VISION_MODEL` 中覆盖。没有 Key 时识别会报错，其他功能不受影响。

也可以使用本机 Ollama，不需要云端 API Key。先安装视觉模型，再将客户端指向 Ollama 的 OpenAI 兼容接口：

```powershell
ollama pull qwen2.5vl:7b
ollama create xingyu-score-recognition -f server/config/ollama-score-recognition.Modelfile
```

```env
OPENAI_API_KEY=ollama
OPENAI_BASE_URL=http://127.0.0.1:11434/v1
OPENAI_VISION_MODEL=xingyu-score-recognition
```

Ollama 必须保持运行，修改 `.env` 后需要重启 `npm run dev:api`。普通文本模型不支持截图识别，模型能力中必须包含 `vision`。

1. 在“星屿积分榜”中切换到“截图识别”，选择批次日期。
2. 选择“队内赛”或“排位赛”；同一批截图只能使用一种比赛类型，不要混传。
3. 上传 JPG 或 PNG 截图（建议一批不超过 20 张），等待人物积分汇总出现。
4. 先核对每个人的汇总分；需要确认时展开该人物，通过原图、识别昵称、名次和单局分数逐条验证。
5. 未匹配昵称会默认展开，必须映射到已绑定积分人物的当前成员，或明确标记为非车队成员；识别错误的名次可直接修正。
6. 名次或人物映射变更后，服务端会重新计算单局分数、去重、局次槽位和人物总分，不要手工填写汇总分。
7. 完全相同的图片会在 AI 识别前自动跳过；内容高度相似但不能确定的图片会同时展示两张原图，必须人工确认“重复图片”或“不同图片”。
8. 同一人当天同一类型满 3 局后会显示提醒并跳过多余局次；重复截图不会占用局次。
9. 若出现“成员未绑定积分人物”，先回到“成员管理”选择已有积分人物并保存，再重新处理该批次。
10. 所有阻塞异常处理完成后“提交确认”才可用。提交时系统再次校验名单版本并原子写入配置，同时通知已打开的前台刷新积分榜。
11. 未提交的新版批次可从“识别记录”点击“继续审核”；没有比赛类型的旧版批次需要重新上传。

本地视觉模型只能降低录入工作量，不能保证昵称和名次完全准确。验证标准是人物汇总中的每一笔分数都能展开并对应到原图；提交前至少核对异常项、低清截图和高分人物，重要批次建议逐人展开核对。

识别规则：队内赛按 max(min(参赛人数, 6) - 名次 + 1, 0) 计分，非车队成员参与人数但不写入积分；排位赛按车队成员游戏名次排序，1 人 1 分、2 人 2/1 分、3 人 3/2/1 分。AI 只提取截图事实，计分、匹配、去重和局次分配全部由服务端确定性代码完成。

## 周末录入

周六、周日的成绩用“周末录入”标签手动填写，不进入截图识别流程。

1. 切换到“周末录入”标签，会自动显示本周的周六和周日两张表。
2. 周六每位积分人物一行，填写“上周积分”“积分”“得分”“总分”；周日填写“积分”“得分”“总分”。
3. 字段原样保存，系统不会改写手动输入的值；周六得分规则是“积分-上周积分”，周日得分规则是“积分-周六积分”，总分按本周滚动计算。
4. 每周一总分重新从当天得分开始，不承接上周总分。
5. 留空的字段保存为空，不会变成 0。
6. 填写后点击页面底部的“保存全部配置”写入运行时配置。

## 实时刷新

后台每次保存配置、提交识别批次后，服务端通过 GET /api/config/events 向所有打开的前台发送 config-updated 事件，前台收到后立即重新请求 /api/config 刷新页面。即使浏览器不支持 Server-Sent Events，窗口重新获得焦点时仍会兜底刷新。

## 公网分享与一键启动

前台 H5 默认只在本机/局域网可见。需要把资讯链接（如 `#news/1`）分享到微信群时，用 Cloudflare 快速隧道生成临时公网链接，无需公网 IP、免账号：

1. 在项目根目录双击 `start-public.bat`（或执行 `powershell -ExecutionPolicy Bypass -File scripts/start-public.ps1`）。
2. 脚本依次启动配置 API（127.0.0.1:3000）、前台 H5（0.0.0.0:4173）和 cloudflared 隧道；已运行的服务自动跳过，最后打印公网链接，例如 `https://xxx.trycloudflare.com`。
3. 把 `公网链接 + #news/<id>` 发给微信联系人，如 `https://xxx.trycloudflare.com/#news/1`；详情页内点“分享”也会复制完整链接。
4. 局域网内的设备仍可用 `http://<本机IP>:4173/` 访问，不受公网隧道影响。

注意：

- 快速隧道链接是临时地址，cloudflared 或电脑重启后会变化，重新运行脚本即可获取新链接。
- 公网链接打开的是公开前台；后台 `/api/login`、`/api/admin` 对公网域名一律返回 404，配置后台仍仅限本机/局域网访问。
- 未安装 cloudflared 时脚本会降级为“仅局域网可访问”提示，本地服务照常启动。
- 进程日志位于 `%TEMP%\xingyu-public-logs`。
