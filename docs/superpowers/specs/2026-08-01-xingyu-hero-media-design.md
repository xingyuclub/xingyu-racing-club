# 星屿首页主媒体支持图片与视频设计

## 目标

首页首屏支持配置图片或视频作为主媒体，并在视频无法加载时显示独立配置的备用图片；保留旧配置兼容性，不改变首页其他模块和配置后台的业务行为。

## 已确认需求

- 后台分别维护“首页主媒体”和“视频失败备用图”。
- 上传后根据接口返回的媒体类型自动识别，不提供手动类型下拉框。
- 图片按原有方式完整显示，保持原比例，不裁切。
- 视频静音、自动播放、循环播放、`playsInline`，不显示控制条。
- 视频加载失败时切换备用图；备用图为空时显示现有空占位。
- 主媒体为空但备用图存在时，直接显示备用图。
- 旧配置中的 `team.heroImage` 自动迁移为图片类型的主媒体，不丢失已有首页素材。

## 配置模型

原始配置中的 `team` 增加：

```js
heroMedia: {
  src: string,
  type: 'image' | 'video',
},
heroFallbackImage: string,
```

迁移规则：

1. 如果已有合法 `heroMedia`，保留其值。
2. 如果没有 `heroMedia` 且存在旧 `heroImage`，根据 `.mp4`/`.webm` 后缀迁移为视频，其余路径迁移为图片；这兼容旧字段中已经保存视频路径的运行时配置。
3. `heroFallbackImage` 缺失时补为空字符串。
4. 迁移后的原始配置不再保存 `heroImage`，由现有配置存储机制负责持久化迁移结果。

主媒体 `src` 允许为空，以支持只配置备用图的场景；`type` 必须为 `image` 或 `video`。备用图允许为空。

## 前台行为

`Hero` 根据 `team.heroMedia` 和 `team.heroFallbackImage` 选择媒体：

- 主媒体为图片：渲染 `<img class="hero-media">`。
- 主媒体为视频：渲染 `<video class="hero-media" autoPlay muted loop playsInline>`，监听 `error` 后切换备用图片。
- 主媒体为空且备用图存在：渲染备用图片。
- 两者都为空，或视频失败且没有备用图：保留当前空占位结构。

图片和视频都使用统一的完整显示样式（`object-fit: contain`），不通过背景平铺或裁切改变素材比例。视频失败状态只在当前媒体实例内切换，不修改后台配置。

## 后台行为

配置编辑器基础信息区域显示两个独立上传项：

- `首页主媒体上传`：接收图片或视频，上传成功后同时写入 `team.heroMedia.src` 和 `team.heroMedia.type`。
- `视频失败备用图上传`：接收图片，上传成功后写入 `team.heroFallbackImage`。

上传接口已有的 MIME 类型识别继续作为唯一类型来源。主媒体上传结果为音频或不支持类型时沿用接口错误，不写入配置。旧的 `heroImage` 不再作为可见编辑字段，但迁移后配置可正常读取。

## 校验与错误处理

- 配置校验要求 `team.heroMedia` 为对象，`src` 为字符串，`type` 为 `image` 或 `video`；`team.heroFallbackImage` 为字符串。
- 迁移会在校验前补齐新字段，保证旧 `site-config.json` 可读取。
- 视频网络错误、解码错误或浏览器拒绝播放均触发备用图切换；不显示控制条，也不要求用户额外交互。
- 备用图片加载失败时回退为空占位，避免破坏首页布局。

## 验证标准

- 单元/组件测试覆盖旧 `heroImage` 迁移、图片主媒体、视频属性、视频错误备用图、仅备用图和空媒体。
- 后台测试覆盖主媒体上传自动写入 `type`、备用图独立写入、旧字段不再显示。
- 配置存储测试覆盖新字段校验和旧配置读写迁移。
- `npm test -- --run` 与 `npm run build` 通过。
- 浏览器至少验证 390、768、1280 三档：图片和视频均无页面级横向溢出，媒体完整显示；视频失败能显示备用图。
