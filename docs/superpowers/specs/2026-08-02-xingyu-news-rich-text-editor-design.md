# 星屿车队新闻富文本编辑设计

日期：2026-08-02

## 1. 目标与范围

本次升级配置后台的新闻管理，让管理员能快速收起已编辑新闻，并在同一张新闻卡片中分别维护首页封面图和带多张插图的富文本正文。公开 H5 继续通过现有新闻弹窗展示详情，不新增文章路由，不改变首页新闻列表结构。

成功标准：

- 已有新闻默认收起，只显示标题、分类、日期和操作按钮；新增新闻自动展开。
- 首页封面图与正文插图具有清晰、独立的编辑入口。
- 正文支持常用排版、链接和多图，并能在当前光标位置插入上传图片。
- 旧新闻无需人工迁移，保存前后的纯文本内容均有兼容回退。
- 富文本经过服务端白名单清洗，公开前台不渲染脚本、事件属性或危险链接。
- 后台与公开弹窗在 390、768、1280 三档视口无页面级横向溢出。

## 2. 已确认方案

采用 Tiptap 作为 React 富文本编辑器，正文保存为经过清洗的 HTML。选择该方案的原因是 Tiptap 已提供稳定的选区、撤销、粘贴和扩展机制，能用较少的项目代码实现完整工具栏与光标处插图。

未采用的方案：

- 自研 JSON 块编辑器：数据结构清晰，但需要自行实现选区、复制粘贴、撤销和工具栏，范围过大。
- 原生 `contenteditable`：依赖少，但浏览器行为和粘贴结果不稳定，常用命令存在废弃问题。

后台采用已确认的单页连续编辑布局。新闻卡片展开后，字段按“基础信息、首页封面图、摘要、富文本正文”的顺序排列，不使用基本信息与正文分页切换。

## 3. 数据模型与兼容

现有新闻字段保持不变：

- `imageSrc`：首页列表和详情顶部使用的封面图。
- `imageAlt`：封面图替代文本。
- `summary`：首页摘要和详情导语。
- `body`：正文纯文本兼容字段。

新增可选字段：

- `bodyHtml`：经过白名单清洗的富文本 HTML。

兼容规则：

1. 旧新闻没有 `bodyHtml` 时，后台把 `body` 作为普通段落载入编辑器，前台继续渲染 `body`。
2. 管理员保存富文本后，同时写入 `bodyHtml`，并从编辑器文档派生无格式纯文本写回 `body`。
3. `body` 继续保持非空校验；`bodyHtml` 存在时必须是字符串，并在持久化前清洗。
4. 不批量重写现有运行时配置。旧记录只在实际编辑保存后获得 `bodyHtml`。
5. 新建新闻模板包含空的 `bodyHtml`，但保存时仍以派生后的非空 `body` 作为正文完整性标准。

正文图片不另建图片数组。上传成功后，图片路径作为 `<img src>` 节点保存在 `bodyHtml` 中，因此可按文章需要插入多张并保持准确顺序。图片替代文本默认使用上传文件的可读原始文件名。

## 4. 后台交互

### 4.1 新闻折叠

- `news` 与 `roster` 都支持单项折叠，但状态仅存在于当前页面，不写入站点配置。
- 页面首次加载时，有标题的已有新闻默认收起。
- 新增的空白新闻默认展开，便于立即编辑。
- 收起摘要格式为“标题 · 分类 · 日期”；空值使用明确的未填写占位。
- 收起状态保留展开、上移、下移和删除操作。

### 4.2 连续编辑布局

展开后的字段顺序为：

1. ID、标题、分类、日期。
2. 首页封面图上传与图片说明。
3. 摘要。
4. 富文本正文编辑器。

封面图仍复用现有 `UploadField` 和上传 API，并限制为图片类型。正文图片由编辑器工具栏触发相同上传 API，上传成功后插入当前光标位置。

### 4.3 富文本工具栏

工具栏提供：

- 撤销、重做。
- 标题层级和正文段落。
- 字体与字号。
- 文字颜色。
- 粗体、斜体、下划线。
- 左对齐、居中、右对齐。
- 无序列表、有序列表。
- 添加或移除链接。
- 上传并插入图片。

字体选项使用无需额外下载的中文系统字体，避免为后台引入外部字体资源。颜色使用原生颜色选择控件。窄屏时工具栏分组换行，不让整个页面横向滚动。

图片上传期间禁用重复触发并显示进度状态。上传失败只显示局部错误，不清空正文、不移动当前新闻的其他字段。上传动作可重复执行，图片节点可在编辑器中选中后删除。

粘贴文本允许保留白名单内的常用格式；粘贴的外部图片、远程热链和 Base64 图片不进入正文，正文图片必须经过现有上传入口。

## 5. 公开前台展示

新闻首页列表继续读取 `imageSrc`、标题、分类、日期和摘要，视觉结构与点击行为保持不变。

新闻详情继续使用现有弹窗：

1. 顶部展示分类、日期和标题。
2. 展示 `imageSrc` 封面图。
3. 以独立导语样式展示 `summary`。
4. 有 `bodyHtml` 时渲染清洗后的富文本；否则渲染 `body || summary`。

正文样式覆盖段落、标题、列表、链接和图片。正文图片保持原始比例并限制在内容宽度内；多张图片按编辑器中的顺序出现。长文章在弹窗内纵向滚动，移动端弹窗接近全屏，桌面端保持适合阅读的最大宽度。正文不能造成页面级或弹窗内容区横向溢出。

## 6. 安全与校验

服务端配置保存链路增加纯函数 HTML 清洗。允许的内容限定为本次工具栏能产生的标签和属性，包括段落、有限标题、列表、加粗、斜体、下划线、文字样式、对齐、链接和图片。

清洗规则：

- 移除 `script`、`style`、`iframe` 等未允许标签。
- 移除所有事件处理属性。
- 链接只允许安全的站内、HTTP、HTTPS 和邮件协议；外部链接补充安全的 `rel`。
- 图片只允许站内上传路径和项目已有的站内素材路径，不允许远程 URL、`data:` 或 `javascript:`。
- 样式只允许工具栏产生的字体、字号、颜色、字重和文本对齐属性，丢弃其他 CSS。

前台只渲染服务端已清洗的 `bodyHtml`。客户端可做防御性清洗，但不能代替服务端持久化前的清洗。

## 7. 组件边界

计划新增或调整的职责：

- `RichTextEditor`：Tiptap 实例、工具栏状态、正文图片上传和错误展示。
- 新闻编辑分支：在 `ConfigEditor` 中处理新闻专属布局、折叠摘要及 `body`/`bodyHtml` 同步。
- HTML 清洗模块：服务端可独立测试的富文本白名单与 URL 规则。
- `NewsFeed`：富文本正文与旧纯文本回退展示。
- 新闻正文样式：后台编辑器内容样式和公开弹窗阅读样式。

不重构配置后台其他树形编辑逻辑，不改变上传 API、素材库或新闻首页列表数据契约。

## 8. 错误与边界状态

- 空正文：服务端沿用 `body` 非空校验，后台显示保存失败详情。
- 图片上传失败：保留当前编辑器内容并允许重试。
- 无封面图：沿用当前配置校验，不在本轮改变新闻封面必填规则。
- 旧数据：缺少 `bodyHtml` 时稳定回退纯文本。
- 非法 HTML：保存时清洗；若清洗后无正文文本，则按空正文拒绝保存。
- 超长正文：编辑器和前台弹窗纵向增长或滚动，不扩展页面宽度。
- 不支持的粘贴格式：降级为允许的格式或纯文本，不保存不可控样式。

## 9. 测试与验收

实施采用测试先行：

1. 后台组件测试先覆盖已有新闻默认收起、新建新闻自动展开、展开后字段保留。
2. 编辑器测试覆盖工具栏格式、纯文本派生、正文图片上传成功与失败、多次插图。
3. 服务端单元测试覆盖允许格式保留，以及脚本、事件属性、危险链接、远程图片和 Base64 图片移除。
4. 配置校验测试覆盖可选 `bodyHtml`、清洗后空正文和旧新闻兼容。
5. 前台组件测试覆盖富文本标题、颜色/字体、列表、链接、多图和旧 `body` 回退。
6. 运行全量 `npm test -- --run` 与 `npm run build`。
7. 浏览器验收后台编辑器与公开新闻弹窗在 390、768、1280 三档视口的排版、滚动和横向溢出。

完成后更新 `AGENTS.md`，记录具体改动、影响范围、验证结果和剩余风险。

## 10. 明确不做

- 不新增独立新闻详情页或路由。
- 不支持表格、引用、代码块、正文视频或嵌入第三方内容。
- 不支持正文图片裁切、拖拽缩放、浮动环绕或图集管理。
- 不自动抓取或持久化粘贴的外部图片。
- 不修改首页新闻列表、配置后台其他模块或公开 H5 的整体视觉方向。
