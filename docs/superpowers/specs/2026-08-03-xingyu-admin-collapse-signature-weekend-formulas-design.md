# 星屿后台折叠、成员签名与周末积分公式设计

日期：2026-08-03

## 目标

本次改动解决四个直接问题：后台顶层栏目默认全部展开、成员视频缺少个性签名、后台积分表无法按数值列降序查看、积分明细缺少周六和周日数据且周末得分与总分仍依赖手填。

## 范围

- 配置后台顶层栏目的折叠交互。
- 成员 `signature` 字段的编辑、保存、兼容和视频弹窗展示。
- 后台“积分明细”和“周末录入”的数值列降序排序。
- 周末积分的跨周继承、得分和总分公式，以及周末数据在积分明细中的展示。

不调整公开 H5 的其他视觉样式，不改变成员、新闻等数组的原始顺序，不批量重写现有运行时配置。

## 后台顶层栏目

后台首次进入时，“基础信息”“统计数据”“成员管理”“新闻管理”“相册管理”“星屿积分榜”“素材管理”全部收起，只显示栏目标题和展开图标。用户点击标题栏后逐项展开或收起。

折叠状态只保存在当前页面组件状态中，不写入站点配置，刷新后重新回到全部收起。展开“成员管理”或“新闻管理”后，内部卡片继续使用现有逐项折叠规则。

## 成员个性签名与视频弹窗

成员原始配置新增可选字符串字段 `signature`。旧配置缺少该字段时迁移为空字符串；新增成员默认签名为空。服务端配置校验允许空字符串并拒绝非字符串值。

成员管理中增加“个性签名”单行文本输入，用于填写一句话。

成员视频弹窗移除成员名称和关闭按钮。非空个性签名显示在视频上方；空签名不渲染占位区域。点击视频或签名内容不关闭弹窗，点击内容区域外的空白遮罩关闭，继续支持 `Esc` 关闭。

## 周末原始数据与公式

`weekendScores` 继续作为周末原始录入数据源。周末的主要手填字段为 `points`，即“积分”。`score` 和 `total` 不再作为后台可编辑值，而由共享积分投影逻辑计算。

周六的 `previousPoints` 按以下优先级确定：

1. 存在上一周周日记录时，使用该成员上一周周日的 `points`，并在后台显示为只读。
2. 不存在上一周周日记录时，允许用户手动填写一次 `previousPoints`，作为首周计算基线。

公式如下：

- 周六得分 = 周六积分 - 周六上周积分。
- 周六总分 = 本周周五总分 + 周六得分。
- 周日得分 = 周日积分 - 本周周六积分。
- 周日总分 = 本周周六总分 + 周日得分。
- 下一周周六的上周积分自动读取本周周日积分。

若本周没有周五明细，周五总分按 `0` 参与计算。下一周的继承值通过日期关系实时派生，不额外复制一份数据，避免修改历史周日积分后出现陈旧副本。

旧数据中已有的 `score` 和 `total` 字段继续兼容读取和保存，避免破坏历史导入文件；当计算所需积分完整时，后台、公开榜单和导出结果以新公式派生值为准。

## 积分明细

“积分明细”的可选日期由 `dailyScores` 与 `weekendScores` 的日期合集生成，默认选择合集中的最新日期。

工作日继续显示日期、积分人物、六局成绩、当日得分和总分。周六显示日期、积分人物、上周积分、积分、得分和总分；周日显示日期、积分人物、积分、得分和总分。周末公式字段在积分明细中只读，周末积分统一在“周末录入”中修改。

## 降序排序

“积分明细”中每个数值列的表头都可点击，包括六局成绩、当日得分、积分、上周积分和总分等当前日期实际显示的数值列。“周末录入”的周六、周日表格也为各自的每个数值列表头提供相同操作。

点击数值表头后，当前表格按该列从大到小排列。排序只影响视图，不修改 `scoreMembers`、`dailyScores` 或 `weekendScores` 的存储顺序。编辑输入时仍通过稳定的成员 ID 和原始行索引更新正确记录。

## 实现边界

- 周末公式集中在共享积分投影模块中，后台和公开页面不重复实现计算规则。
- 后台编辑器从共享投影结果读取 `score` 和 `total`。
- 只为现有组件增加必要状态和字段，不引入新的状态管理库或通用表格抽象。
- 保留现有 Excel 和旧配置兼容链路；如导出包含周末结果，应使用共享公式生成的值。

## 验收标准

1. 后台初次渲染时七个顶层栏目全部收起，能够独立展开和收起。
2. 个性签名能够编辑、保存并重新加载，非空签名显示在对应成员视频上方。
3. 视频弹窗不显示成员名称和关闭按钮；内容点击不关闭，空白遮罩点击和 `Esc` 可关闭。
4. 积分明细能选择并显示周六、周日日期和对应字段。
5. 首周缺少上一周周日数据时可手填周六上周积分；存在上一周周日数据时自动继承且只读。
6. 周六、周日得分与总分严格按确认公式计算，修改积分后立即联动。
7. 下一周周六自动显示上一周周日积分。
8. 两个后台积分标签中的每个数值表头均能按从大到小排序，且不会改动底层数据顺序或错写成员。
9. 定向测试、全量测试和生产构建通过；桌面及移动视口无页面级横向溢出，后台表格只在自身容器内滚动。
