# 星屿车队 H5 COS 媒体与上线前收口设计

日期：2026-08-06

## 1. 背景

当前公开 H5、配置后台、积分榜和截图识别均运行在本机 Node 服务中。公网分享暂时依赖免费隧道，媒体资源也由本机上传目录提供。现有运行时配置包含大量待重新确认的成员、图片、视频、相册、新闻和音乐素材。

上线前需要完成以下收口：

- 将后续媒体上传迁移到腾讯云 COS，并通过 CDN 地址提供公开访问。
- 图片保留原图，同时生成 WebP 缩略图供列表和首屏使用。
- 将公开前台与 API 收口为生产构建加单个 Node 服务，通过免费 Cloudflare 快速隧道分享。
- 在最终确认后重置非积分配置为通用占位内容。
- 完整保留星屿积分榜、Excel 数据、截图识别历史和审计证据。

当前工作区仍有其他会话产生的大量未提交改动。本设计阶段不清空配置、不修改业务代码、不暂存、不提交，也不接触其他会话正在修改的文件。

## 2. 目标

### 2.1 核心目标

1. 为腾讯 COS 自动上传、缩略图和 CDN 访问建立清晰的数据与服务边界。
2. 为非积分配置提供可预览、可回滚、可校验的重置流程。
3. 保证积分榜和截图识别数据在重置前后完全一致。
4. 建立唯一的生产公网启动方式和从零部署指南。
5. 保持后台仅限本机或受信任局域网访问。

### 2.2 非目标

- 本阶段不购买或部署云服务器。
- 不把 Node API 或配置后台部署到腾讯云。
- 不把后台管理入口开放到公网。
- 不执行运行时配置清空。
- 不删除现有本地媒体文件。
- 不迁移或合并 Pit Wall 分支。
- 不解决免费隧道的随机域名、偶发断线或服务等级限制。

## 3. 当前并行工作保护

实施开始前必须满足以下前置条件：

1. 其他会话明确完成或停止修改当前工作区。
2. 重新运行 `git status --short --branch`，逐项确认所有修改的归属。
3. 不得使用 `git reset --hard`、`git checkout --` 等方式覆盖现有改动。
4. 不得把不同会话的未完成代码混入本功能提交。
5. 运行时配置与上传目录仍按现有规则不进入 Git。

如工作区仍不稳定，只允许继续完善独立文档，不进入代码实施或数据重置。

## 4. 数据保留边界

### 4.1 必须完整保留

运行时配置中的以下字段必须原样保留：

- `scoreMembers`
- `dailyScores`
- `weekendScores`

以下识别与审计数据也必须完整保留：

- `server/data/score-recognition/` 下的识别批次索引和运行时状态。
- `server/storage/score-recognition/` 下的原始截图、证据文件和批次目录。
- 已提交、待确认、失败和历史批次的草稿及审计信息。
- Excel 导入、导出和积分人物映射所依赖的原始积分数据。

### 4.2 `memberAliases` 处理

`memberAliases` 当前引用 `roster` 成员 ID。成员阵容清空后，原别名无法继续通过配置校验。因此重置流程必须：

1. 在清空前把完整 `memberAliases` 写入时间戳备份。
2. 将运行时配置中的 `memberAliases` 暂时重置为空数组。
3. 新成员重新录入后，只恢复仍能明确映射到新成员 ID 的别名。
4. 禁止用姓名猜测自动恢复映射。

### 4.3 不删除旧媒体

重置只解除运行时配置对旧媒体的引用，不删除 `server/storage/uploads/` 中的文件。旧媒体后续由用户人工确认，再决定重新上传、归档或删除。

## 5. 非积分配置重置

最终重置时，以下数据改为通用占位状态：

- `team`：使用通用车队名称和 Hero 占位文案，不保留旧媒体引用。
- `stats`：保留四项通用标签，数值改为占位值。
- `roster`：清空为空数组，不生成虚假成员。
- `albums`：清空业务照片和视频，公开页面显示统一空状态。
- `news`：清空业务资讯，公开页面显示统一空状态。
- `newsCategories`：保留后台正常新建资讯所需的最小通用分类。
- `music`：清空音频地址，封面使用内置占位图。
- `memberAliases`：按上一节规则备份后清空。

重置脚本不得直接覆盖文件，必须先生成预览报告。只有报告通过并获得用户明确确认后，才允许原子写入运行时配置。

## 6. 占位资源设计

项目提供以下内置占位资源：

- Hero 横版占位图。
- 成员肖像占位图。
- 相册和资讯占位图。
- 音乐封面占位图。

占位资源不得复用以前的全家福、成员原图或其他待确认媒体。占位图只负责保证布局完整，不代表真实业务内容。

空成员、空相册和空资讯不通过伪造配置项实现。对应组件应显示模块级空状态，后台仍可正常新增真实内容。

## 7. Hero 媒体行为

Hero 使用以下加载链路：

```text
后台配置的 COS 视频
  -> 静音、循环、playsInline 自动播放
  -> 视频加载错误、播放被拒绝或规定时间内未开始播放
后台配置的备用图片
  -> 图片加载错误
项目内置 Hero 占位图
```

具体规则：

- 视频存在时立即尝试自动播放。
- 为满足移动端浏览器自动播放限制，视频保持静音和行内播放。
- 视频触发 `playing` 前，备用图片持续显示在底层，避免黑块。
- 视频开始播放后再显示视频画面。
- 视频失败不能清空 Hero 区域，必须进入备用图片链路。
- 后台备用图片失败后，只允许回退到新的通用 Hero 占位图。
- 旧 `/images/hero-home.png` 全家福不得继续作为默认回退资源。

## 8. 腾讯 COS 媒体架构

### 8.1 服务端配置

COS 凭据只由 Node 服务读取，使用环境变量保存：

- Secret ID
- Secret Key
- Bucket
- Region
- COS 公共访问基础地址或 CDN 基础地址

真实凭据不得写入源码、前端构建、运行时公开配置、日志或 Git。

`.env.example` 只记录变量名称和用途，不包含真实值。

### 8.2 上传流程

后台上传流程调整为：

1. 校验登录会话、文件类型和文件大小。
2. 图片使用现有 `sharp` 生成 WebP 缩略图。
3. 原图和缩略图分别上传 COS。
4. 视频和音频保留原始文件，不做有损转码。
5. COS 上传完成后才返回可保存的公开 URL。
6. 上传失败时不得把半成品 URL 写入配置。
7. 服务端返回原始 URL、展示 URL、媒体类型和原始文件名。

### 8.3 图片使用规则

- Hero 备用图使用适合首屏的优化图片。
- 风采轮播、成员阵容、资讯列表和相册缩略图使用 WebP 缩略图。
- 打开照片详情时使用原图 URL。
- 原图与缩略图必须能追溯到同一次上传。
- 不通过降低原图质量来换取列表加载速度。

### 8.4 视频和音乐

- 视频 URL 直接指向 COS/CDN，并支持浏览器分段请求。
- Hero 视频按第 7 节自动播放。
- 成员和相册视频继续在用户打开弹窗后播放。
- 音乐继续沿用实施开始时项目已有的播放、暂停和关闭行为，本需求只替换资源来源，不改变交互规则。

## 9. 生产公网架构

上线前的临时公网架构为：

```text
访客浏览器
  |-- 图片、视频、音乐 --> 腾讯 COS/CDN
  `-- HTML、JS、CSS、公开 API --> Cloudflare 快速隧道 --> 本机 Node:3000
                                                    `--> dist + Express API
```

生产入口统一为：

1. 安装依赖。
2. 配置本地管理员和服务端环境变量。
3. 执行完整测试。
4. 执行 `npm run build`。
5. 启动 `node server/index.js`，由端口 `3000` 同时提供 `dist` 和 API。
6. Cloudflare 快速隧道指向 `http://127.0.0.1:3000`。
7. 输出临时公网 HTTPS 地址并做健康检查。

端口 `4173` 的 Vite 服务只用于开发和局域网调试，不作为最终公网生产入口。

免费隧道的已知限制必须写入部署指南：

- 隧道或电脑重启后公网地址可能变化。
- 本机必须保持开机，Node 和隧道进程必须保持运行。
- 免费节点可能偶发连接失败或限速。
- COS/CDN 只能减少媒体传输压力，不能消除免费隧道的可用性风险。

## 10. 公网安全边界

- 公网允许访问公开页面、公开静态资源、`GET /api/config` 和 SSE 配置事件。
- 公网访问 `/api/login`、`/api/admin` 及后台页面时必须返回 404。
- 本机和受信任局域网继续允许后台登录。
- `server/config/admin.local.json`、COS 密钥和本地 `.env` 不得进入 Git。
- 日志不得输出管理员密码、会话 Cookie、COS Secret 或完整鉴权头。

## 11. 重置工具设计

未来新增一次性上线准备工具，至少支持：

- `dry-run`：只生成差异和校验报告，不写文件。
- `apply`：明确确认后执行原子写入。
- 自动生成完整运行时配置备份。
- 自动生成 `memberAliases` 独立备份。
- 统计重置前后的积分人物、工作日、周末日和积分行数。
- 统计识别批次数、索引文件大小、证据文件数量和总字节数。
- 校验所有积分行继续引用有效的 `scoreMembers` ID。
- 检查新配置不再引用旧全家福或旧业务媒体。

任何积分或识别校验不一致时，`apply` 必须拒绝写入。

## 14. 验收标准

### 14.1 数据安全

- 重置前后 `scoreMembers` 深度一致。
- 重置前后 `dailyScores` 深度一致。
- 重置前后 `weekendScores` 深度一致。
- 识别批次索引、批次数、原始截图数和证据总字节数一致。
- 所有积分行继续引用有效积分人物 ID。
- 完整备份可恢复到重置前状态。

### 14.2 媒体与前台

- 后台图片上传成功后同时获得原图和 WebP 缩略图。
- 列表使用缩略图，详情使用原图。
- Hero 视频自动播放成功时不显示黑块。
- Hero 视频失败时显示后台备用图片。
- 备用图片失败时显示新的内置占位图。
- 项目不再把旧全家福作为默认 Hero 图片。
- 空成员、空相册和空资讯页面结构完整且无虚假数据。

### 14.3 构建与浏览器

- 全量测试通过。
- `npm run build` 通过。
- ExcelJS 保持后台动态加载。
- 390、768、1280 视口无页面级横向溢出。
- 前台和后台控制台无新增错误。
- 视频、原图和缩略图的 URL、内容类型和缓存行为正确。

### 14.4 公网与安全

- 公网根路径和 `/api/config` 返回 200。
- 公网 `/api/login` 和 `/api/admin` 返回 404。
- 本机后台能够正常登录、上传和保存。
- 隧道脚本只启动生产 Node 服务和 Cloudflare 隧道。
- 用户可以按部署指南从空环境完成启动并取得公网地址。
