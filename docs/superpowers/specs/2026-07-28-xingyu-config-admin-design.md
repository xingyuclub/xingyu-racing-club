# 星屿车队配置后台设计

## 状态

- 设计已由用户确认
- 本文只定义第一版范围和验收标准，不包含实现代码
- 目标：减少频繁修改 `src/data/teamData.js` 的维护成本

## 1. 目标与边界

第一版提供一个仅供本机或局域网使用的密码保护配置后台。管理员可以通过表单维护当前 H5 的全部业务内容，并上传图片、视频和音频。保存后，前台刷新页面即可读取最新配置。

第一版不包含数据库、公网账号体系、多管理员、角色权限、评论、支付、自动抓取比赛数据和独立发布流程。

由于账号密码固定写在本地配置文件中，服务不得直接暴露到公网使用。

## 2. 总体架构

使用一个 Node.js 服务同时提供：

- 已构建的 React 前台 H5
- `/admin` 后台管理页面
- 配置读取和保存 API
- 登录和退出 API
- 素材上传和删除 API

目录职责：

```text
server/
  index.js                    # 服务入口和 API
  config/admin.local.json     # 本机管理员账号密码，不提交 Git
  config/admin.example.json   # 配置示例，不含真实密码
  data/site-config.json       # 运行时网站配置
  data/site-config.json.bak   # 最近一次保存前的备份
  storage/uploads/            # 运行时上传素材
src/
  admin/                      # 后台页面和表单组件
```

首次启动时，如果 `server/data/site-config.json` 不存在，则从现有 `src/data/teamData.js` 生成初始配置。运行时前台以 JSON 配置为准，`teamData.js` 保留为初始化模板和异常回退数据。

## 3. 配置数据模型

运行时 JSON 保留当前 `teamData` 的原始数据结构，减少前台改动：

- `team`：车队名称、标签、口号、首屏图片
- `stats`：四项统计卡片
- `roster`：成员资料、编号、身份、积分、胜场、头像、视频地址
- `albums`：相册、封面和照片/视频条目
- `dailyScores`：日期、星期、成员每日分项成绩和总分
- `news`：资讯标题、分类、日期、图片、摘要和正文
- `music`：音乐文件、封面和显示信息。当前初始值来自 `App.jsx` 中的 `/audio/launch-now.mp3` 和 `/images/music-avatar.png`，实施时迁移到 JSON。

以下内容不由后台单独保存：

- `gallery`：由 `albums[].photos` 派生
- `leaderboard`：由 `roster` 的积分和胜场派生
- `featuredMembers`：由 `roster` 的排序和展示规则派生

后台表单可以编辑这些内容的来源字段，前台继续负责派生展示数据，避免同一内容出现两份需要同步的配置。

## 4. 后台功能

后台使用分模块表单，不要求管理员直接编辑 JSON。

### 基础信息

编辑车队名称、显示标签、口号、首屏图片和音乐信息。

### 统计数据

编辑统计卡片的标签和值，保留现有四项卡片结构，并支持编辑单身贵族的男女数量。

### 成员管理

支持新增、编辑、删除和排序。字段包括编号、姓名、身份、积分、胜场、头像和视频地址。头像和视频字段提供上传入口。

### 新闻管理

支持新增、编辑、删除和排序。字段包括标题、分类、日期、封面、替代文本、摘要和正文。封面支持上传。

### 相册管理

支持新增、编辑、删除相册，维护相册名称、日期、封面和照片/视频条目。每个条目支持标题、日期、替代文本、精选状态、媒体类型和素材上传。

### 每日成绩

支持按日期新增和编辑每日记录，维护成员、车队赛分项、公开赛分项、单日得分和总分。成员名称和 ID 优先从成员列表选择，避免手填造成关联错误。

### 音乐与素材

音乐配置支持上传音频和封面。素材管理页显示已上传文件、类型、大小、访问路径和删除操作，并提供复制路径能力。

## 5. API 与数据流

公开接口：

- `GET /api/config`：前台读取经过基础校验的网站配置

认证接口：

- `POST /api/login`：校验本地管理员账号密码并设置 HttpOnly Cookie
- `POST /api/logout`：清除登录 Cookie

后台接口：

- `GET /api/admin/config`：读取完整配置
- `PUT /api/admin/config`：校验并保存完整配置
- `POST /api/admin/upload`：上传图片、视频或音频
- `GET /api/admin/uploads`：列出上传目录中的素材
- `DELETE /api/admin/uploads/:name`：删除指定素材

保存流程：

1. 后台表单收集当前配置。
2. 服务端检查必需字段、数组类型、数字字段和成员关联。
3. 先把当前 JSON 复制为 `.bak`。
4. 写入临时文件，成功后替换正式 JSON。
5. 返回保存成功，前台下一次刷新读取新配置。

上传流程：

1. 服务端检查 MIME 类型和文件扩展名。
2. 服务端重新生成文件名，禁止客户端路径进入保存路径。
3. 文件写入 `server/storage/uploads/`。
4. 返回以 `/uploads/` 开头的前台访问路径。
5. 后台将路径填入当前表单字段。

## 6. 登录与安全约束

`server/config/admin.local.json` 仅保存单个管理员账号和密码，并加入 `.gitignore`。仓库只保留不含真实密码的示例文件。

登录成功后使用 HttpOnly、SameSite Cookie 保存内存会话令牌。服务重启后会话失效。未登录用户可以访问前台公开配置，但不能读取后台完整配置、保存配置、上传或删除素材。

上传默认限制：图片 10 MB，视频和音频 200 MB。服务端同时校验扩展名和 MIME 类型。所有删除操作限制在 `storage/uploads/` 目录内。

该认证方案只满足本机/局域网后台的使用场景，不能作为公网管理后台的安全方案。

## 7. 异常处理与回退

- 登录失败时返回通用错误，不暴露账号是否存在。
- 配置保存校验失败时不覆盖原配置，并显示具体字段错误。
- 写入失败时保留原 JSON 和备份文件。
- 前台读取 API 失败或返回无效配置时，回退到内置初始数据，避免白屏。
- 上传失败时不写入配置字段，并清晰提示失败原因。
- 删除不存在或目录外文件时返回错误，不执行删除。

## 8. 验收标准

### 功能

- 管理员可以登录、退出，未登录无法修改数据。
- 所有当前配置模块都能通过表单编辑并保存。
- 图片、视频、音频可以上传并在前台正常访问。
- 保存配置后，前台刷新即可显示新内容。
- 删除素材不会删除配置文件或目录外文件。

### 数据一致性

- 前台只维护一份运行时 JSON 配置。
- 相册、排行榜和精选成员等派生数据不会要求后台重复编辑。
- 成员 ID、每日成绩和成员列表之间保持有效关联。
- 保存前会生成可用的 `.bak` 文件。

### 回归验证

- `npm test` 通过。
- `npm run build` 通过。
- 后台登录、配置保存、上传和删除接口有自动化测试。
- 浏览器验证手机尺寸下的前台显示和后台表单基本布局。
