# 星屿车队 H5 Pit Wall UI/UX 重设计

## 目标

完整重设计星屿车队公开 H5 的 UI/UX，包括首页、相册页、成员视频弹窗、照片弹窗、资讯详情、日期积分查询和音乐浮窗。

本轮只改变视觉系统、信息结构、响应式布局和动效表现。现有业务功能、数据字段和配置后台保持不变。

主要用户是正在了解车队的潜在新成员。页面需要让他们快速感知真实车队、成员阵容、成绩和活动氛围，并形成“这支车队专业、有实力、值得进一步了解”的印象。本轮不新增招募按钮或联系方式。

## 当前问题

- 当前蓝白风格接近通用手游官网，缺少星屿车队自己的识别度。
- 首页内容密度失衡，模块之间存在大段空白和滚动断层。
- 排版、卡片和层级不够统一，真实成员与成绩没有成为视觉主体。
- 动效依赖元素进入可见状态，异常或截图场景可能导致内容长时间不可见。
- 桌面端更像被放大的手机页面，没有充分利用横向空间。
- 相册页、弹窗和音乐浮窗缺少统一的产品级视觉语言。

## 已确认约束

- 改造范围为完整公开 H5，不包含配置后台。
- 保留蓝色作为品牌识别色，允许加入黑、银和少量状态辅助色。
- 只使用项目现有图片和素材，不新增或生成视觉素材。
- 可以重排首页模块和增加页面内导航。
- 不新增或删除业务功能，不改变数据字段含义。
- 动效应明显但流畅，有镜头感和滚动节奏，不影响阅读和性能。
- 不新增实际招募入口。
- 队员圆柱滚动、暂停、拖拽控制和点击详情必须保留。
- 相册继续使用“文件夹 -> 照片”的两级结构。
- 日期积分继续按日期展示六局成绩、当日得分和累计总分。

## 方向契约

**THESIS**

公开 H5 是一条数字化车队维修区，不是通用蓝白手游官网。真实车队合照、成员、积分和记录像 Pit Wall 工作区一样连续展开。

**OWN-WORLD**

银灰结构面、性能黑区域、赛道蓝状态标记和少量警示黄。组件采用直线、编号、轨道和 `0-4px` 小圆角，不使用玻璃卡片、霓虹发光和大面积渐变。

**STORY**

用户先看到真实车队和核心数据，再认识成员与完整阵容，随后查看积分、相册和持续更新的资讯。整个页面证明车队真实存在、持续活动并具备明确秩序。

**FIRST VIEWPORT**

现有车队合照全幅铺开，“欢迎来到星屿车队”作为主要标题；少量赛季和车队编号形成结构。首屏高度约 `72-78svh`，底部露出紧贴图片的数据带。

**FORM**

选定方向为 `Pit Wall / 车队维修区`，方向种子为 `282e3eff`。首页采用连续工作带结构，模块通过背景面、轨道线和编号自然衔接，不使用独立悬浮卡片堆叠。

## 视觉系统

### 色彩

- 维修区银灰 `#E8EDF2`：页面主背景和结构面。
- 结构白 `#F8FAFC`：正文、表格和高可读数据区域。
- 性能黑 `#101820`：成员、媒体和关键性能区域。
- 赛道蓝 `#1769FF`：当前状态、排名、导航和焦点。
- 石墨文字 `#17202A`：浅色区域主要文字。
- 金属中灰 `#647180`：辅助文字、边框和未激活状态。
- 警示黄 `#F4B400`：只用于少量状态提示。

蓝色不能覆盖所有标题、数字和边框。同一视口内只强调真正重要的状态与交互。

### 字体

- 英文、编号、积分：`Bahnschrift Condensed, Arial Narrow, sans-serif`。
- 中文和正文：`Microsoft YaHei, Segoe UI, Arial, sans-serif`。
- 字距保持正常，主要通过尺寸、重量和位置建立层级。
- 首屏之外不使用超大标题；内容面板标题保持紧凑。

### 形状与深度

- 以直线、切角、窄矩形和轨道为主要几何语言。
- 圆角限制在 `0-4px`，圆形仅用于状态点、音乐旋钮和必要图标。
- 静止内容默认无悬浮阴影，通过色面、边框和裁切建立层级。
- 阴影仅用于弹窗、吸顶导航和当前交互状态。

## 首页信息结构

### 1. 首屏车队主视觉

- 使用现有合照，不新增素材。
- 保留“欢迎来到星屿车队”。
- 增加克制的车队编号、赛季标记和滚动进度结构。
- 手机与桌面都必须露出下一段数据带。
- 图片裁切应优先保证车队主体可见。

### 2. 车队遥测数据

- 四项现有统计紧贴首屏。
- 桌面横向四列，手机紧凑 `2×2`。
- 使用计时数据带语言，不使用白色悬浮卡和大阴影。

### 3. 页面内导航

- 增加 `成员 / 积分 / 相册 / 动态` 页面内锚点导航。
- 手机可横向滑动，当前区域使用蓝色状态标记。
- 桌面保持轻量吸顶，不遮挡标题和内容。

### 4. Driver Bay

- 核心成员和完整阵容组合成连续的成员工作区。
- 核心成员先出现，展示真实的人和成员身份。
- 完整阵容保留圆柱滚动、暂停、拖拽、回速和点击详情。
- 素材缺失时使用明确的编号档案占位，不伪造头像。

### 5. 星屿积分榜

- 紧跟成员区，作为车队实力证明。
- 前三名使用位置编号、状态条和积分刻度强化，不使用金银铜奖牌。
- 日期查询入口保持在标题操作区。
- 长名称和大积分值不得改变行高或撑破布局。

### 6. 相册空间

- 使用现有“一张主图 + 紧凑缩略图”内容结构。
- 图片通过编号、日期和赛道裁切框组成联系表。
- “查看更多相册”继续进入原有相册页面。

### 7. 车队动态

- 使用赛事日志式时间轴。
- 日期、分类、标题和摘要建立清晰的扫读层级。
- 页面末尾使用现有车队口号作为结束带，不新增按钮。

## 相册页

- 顶部显示返回入口和当前相册路径。
- 相册文件夹使用编号、日期和封面组成的横向档案条。
- 手机照片网格为两列，重点照片可跨两列。
- 桌面使用更密集的联系表布局。
- 视频素材保留明确播放标记，不只依靠颜色区分。
- 浏览器返回键和 `#album` 路由行为保持不变。

## 弹窗

### 成员视频

- 使用深色 `Driver Inspection Bay`。
- 媒体内容为主体，成员编号、名称和角色放在底部信息轨。
- 手机接近全屏，桌面居中但不过度缩小媒体。

### 照片预览

- 使用深色检查台，图片不套装饰卡片。
- 标题和日期位于固定信息栏。

### 资讯详情

- 使用浅色赛事记录页。
- 优先改善标题、日期、正文宽度和阅读层级。

### 日期积分查询

- 桌面使用左侧日历、右侧当日成绩的双区布局。
- 手机保持日历在前、六局成绩与累计总分在后的顺序。
- 当前日期、可查询日期和选中日期使用不同形状与填充状态，不能只改变透明度。
- 空日期保持明确空状态，不显示伪造成绩。

## 音乐浮窗

- 改为右下角小型通讯旋钮。
- 保留播放、暂停和长按关闭。
- 播放状态使用细环进度和轻微节奏反馈，不持续旋转或发光。
- 避让弹窗操作、相册返回和页面导航。
- 保持清晰无障碍名称和至少约 `44×44px` 触摸区域。

## 组件边界与数据流

- `App.jsx` 继续通过 `useSiteConfig` 获取 `siteData`，不增加第二套页面数据或展示专用配置。
- 首页只重排现有 `Hero`、`StatsBar`、`FeaturedMembers`、`Roster`、`Leaderboard`、`GalleryPreview` 和 `NewsFeed` 组件。
- 页面内导航通过现有模块的语义 `id` 定位，不引入路由库或新的业务状态。
- 相册继续使用现有 hash 导航和 `AlbumPage`；所有弹窗继续由 `App.jsx` 中现有选择状态控制。
- 日期积分继续消费 `hydrateSiteData` 的派生结果，不在展示组件中重新计算积分。
- 设计 token 集中在全局样式入口，组件样式按现有 className 组织；只在语义或状态无法表达时补充最少的结构元素和 className。

## 空状态与异常状态

- 成员没有头像时显示编号档案占位，不显示虚构人物图片。
- 相册、资讯或日期积分为空时保留真实的空状态文字，不用装饰内容填满页面。
- 图片或视频加载失败时，容器尺寸保持稳定并显示可识别的不可用状态。
- 弹窗打开后焦点进入弹窗，关闭后返回触发控件；关闭按钮始终可见且可使用键盘操作。
- 内容默认可见，CSS 或观察器增强失败时不能形成空白模块。

## 动效

- 首屏只执行一次短镜头：图片轻微推进，标题和数据带分两拍进入，总时长约 `900ms`。
- 页面不使用滚动劫持或强制视差。
- 模块只使用短距离进入、轨道线展开和数据状态切换。
- 同一视口最多出现 `1-2` 个主要动效。
- 内容默认可见，动效通过增强类启用；观察器失败时不能留下空白。
- 弹窗快速淡入和进入，关闭立即响应。
- `prefers-reduced-motion: reduce` 下取消位移、推进和连续装饰动画。

## 响应式与可访问性

- 以 `375px` 为手机基准，验证 `390px`、`768px`、`1024px`、`1440px`。
- 手机保持单一阅读路径，桌面只在比较型内容使用双栏。
- 页面级横向滚动为零；仅阵容和明确宽表允许局部滚动。
- 所有按钮和图标触摸区域至少约 `44×44px`。
- 所有交互支持键盘操作并具有可见焦点。
- 长中文名、特殊 Unicode 车队名、大积分值和长资讯标题必须正确换行或截断。
- 文字和控件满足清晰对比度，颜色不是唯一状态指示。

## 性能与实现边界

- 不新增动画库、轮播库、UI 框架或图片素材。
- 优先复用现有 React 组件、CSS 和 `IntersectionObserver`。
- 优先使用现有 WebP 图片，避免重复加载大尺寸 PNG。
- 避免大面积 `backdrop-filter`、持续阴影动画和昂贵滤镜。
- 可以增加不影响业务的锚点、语义容器和样式类。
- 可以重新组织 CSS，但不借机重构数据层或配置后台。

## 非目标

- 不设计或修改配置后台。
- 不新增招募、联系、登录、分享或外部跳转功能。
- 不修改积分计算、数据模型、上传或 Excel 流程。
- 不新增真实素材、生成图片或虚构车队证明。
- 不删除相册两级结构、成员详情、积分查询或音乐控制。

## 验证标准

- 首页、相册页、所有弹窗和音乐浮窗使用统一 Pit Wall 视觉系统。
- 首个视口显示真实车队、名称和至少一部分核心实力信号。
- 手机端没有大段无意义留白，内容默认可见且滚动连续。
- 所有现有业务交互和数据展示保持可用。
- 375、390、768、1024、1440 视口无页面级横向溢出、遮挡和不可读文本。
- 队员圆柱、相册导航、媒体弹窗、资讯详情、积分查询和音乐控制完成浏览器交互验证。
- 键盘焦点、颜色对比、触摸区域和减少动态检查通过。
- `npm test` 和 `npm run build` 通过。
- 生成主要视口截图，与方向契约和 `DESIGN.md` 逐项核对。
