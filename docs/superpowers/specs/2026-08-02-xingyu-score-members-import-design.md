# 星屿积分身份与首次 Excel 导入设计

日期：2026-08-02

## 目标

将成员展示名单与积分榜人员拆开，使用用户提供的 `星屿杯积分明细NEW.xlsx` 完成 KW27-KW31 首次历史导入，同时保证后续截图识别继续使用后台配置的成员名称和别名。

## 核心规则

1. `roster` 只代表后台配置的当前成员，用于成员阵容、头像、角色、视频和截图识别候选。
2. `scoreMembers` 代表积分榜人物，用于工作日积分、周末积分、排行榜和日期明细。
3. 首次 Excel 导入不读取、不匹配也不修改 `roster`，人员完全来自 Excel。
4. 积分身份使用 `normalizeNickname(name)` 生成匹配键：移除不可见字符和 `ˣʸ༩·` 前缀、清理首尾空格并统一大小写。
5. 有前缀与无前缀的名称只要前缀后的名字一致，就属于同一积分人物。
6. 同一积分人物跨周名称写法变化时，显示名使用 Excel 中最后一周出现的原文。
7. 后续截图仍先按最新 `roster` 和 `memberAliases` 识别后台成员，再用该成员名称的积分身份键查找 `scoreMembers`；不存在时新增积分人物。

## 数据模型

`site-config.json` 新增顶层字段：

```js
scoreMembers: [
  {
    id: 'score:%E9%9D%92%E5%B1%B1',
    name: 'ˣʸ༩·青山',
    basePoints: 0,
    wins: 0,
  },
]
```

`dailyScores[].rows[].id` 和 `weekendScores[].rows[].id` 改为引用 `scoreMembers.id`。`roster.id` 不再是积分记录的身份边界。

积分 ID 由归一化后的名称确定性生成，确保 Excel 导入和后续截图对同一名称得到相同 ID。原始显示名只用于展示，不参与 ID 稳定性。

## 旧配置迁移

旧配置没有 `scoreMembers` 时，运行时迁移从现有 `roster` 生成兼容的积分人物，并保留原有 ID，使已有积分记录不失效。迁移只解决旧配置读取；首次 Excel 导入确认后，KW27-KW31 的积分人员和记录以 Excel 结果为准。

## 首次 Excel 导入

解析器只接受：

- `S53-kw27`
- `S53-kw28`
- `S53-KW29`
- `S53-KW30`
- `S53-KW31`

导入流程：

1. 动态定位星期、局次和周末字段，不依赖固定绝对列号。
2. 从 Excel 昵称生成积分身份，不传入后台 roster 或别名。
3. 按归一化名称合并跨周同一人物，保留最后一周的 Excel 显示名。
4. 生成 2026-06-29 至 2026-08-02 的工作日和周末预览。
5. 校验日期、数组长度、数值类型和同日 ID 唯一性。
6. 使用配置存储的原子写入流程保存，写入前生成 `site-config.json.bak`。
7. 覆盖 KW27-KW31 范围内的历史积分，范围外记录保留。
8. 首次导入后的 `scoreMembers` 以 Excel 人员为基础；范围外记录引用的积分人物必须保留，避免悬空 ID。

首次导入不修改原 Excel 文件，不把 Excel 人员加入成员阵容。

## 前端与后台

- 首页 `Roster` 继续读取 `roster`。
- 首页 `Leaderboard` 改为读取 `scoreMembers` 的积分投影。
- 日期积分弹窗使用 `scoreMembers` 显示姓名。
- 积分明细编辑和周末录入使用 `scoreMembers` 作为人员选项。
- 成员管理仍只编辑 `roster`。
- 统计栏“队员数量”仍由 `roster.length` 派生。

## 后续截图识别

1. AI 识别提示仍使用后台 `roster` 名称。
2. 昵称和别名先匹配到后台成员。
3. 后台成员名称再按积分身份键解析到 `scoreMembers.id`。
4. 已有同名积分人物时继续累计历史总分。
5. 不存在时创建新的 `scoreMembers` 项，名称采用后台配置名称，初始积分为 0。
6. 截图识别期间名单变化仍使用现有 roster 版本校验阻止过期提交。

## 校验与失败处理

- `scoreMembers.id` 必须非空且唯一。
- `scoreMembers.name` 归一化后必须唯一，防止有前缀和无前缀重复成两人。
- 工作日和周末行必须引用存在的 `scoreMembers.id`。
- Excel 解析出现坏表、重复身份或非法数值时停止写入，保留当前配置。
- 配置写入失败沿用现有临时文件、备份和回滚机制。
- 成功写入后触发现有 `config-updated` SSE，已打开的前端自动刷新。
